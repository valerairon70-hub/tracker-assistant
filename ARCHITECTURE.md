> Актуализировано 2026-07-24. Этот файл описывает то, что реально работает в проде — не план, а факт.

## Компоненты

### Фронтенд — `index.html`
Один файл (~13 000 строк), чистый HTML/CSS/JS, без сборки и CDN. Вкладки: «Расшифровать», «Пригласить», «Статистика», «Клиенты», «Кто я?», плюс страница тарифов `pricing.html` отдельным файлом.

Загруженные скриншоты сжимаются в браузере перед отправкой (`canvas`, до 900px по ширине, JPEG качеством 72%) — экономит трафик и токены на vision-запросах.

### `api/analyze.js` — ядро AI-логики
Один файл, ~3200 строк, обрабатывает все режимы анализа через параметр `mode`:

| Режим | Что делает | Модель |
|---|---|---|
| decode (по умолчанию) | Расшифровка диаграммы трекера + мед.документов → причины, протокол, скрипт | `claude-sonnet-5` |
| chat | Диалог-продолжение после расшифровки | `claude-sonnet-5` |
| analytics | Аналитика по накопленным данным | `claude-sonnet-5` |
| compare | Сравнение двух сессий клиента («было / стало») | `claude-sonnet-5` |
| invite, reengagement, rejection, objection, reactivate, dialog, thinking, positioning, client-action, story, result, checkin | Более простые шаблонные задачи (скрипты касаний, обработка возражений, позиционирование и т.д.) | `claude-haiku-4-5` |

Decode-запрос — потоковый (SSE, `stream: true`), с `effort: 'medium'` (снижает время генерации, см. Фаза 15) и кэшированием системного промпта (`cache_control: ephemeral`, TTL 1 час) — экономит токены при повторных запросах.

**Лимит скриншотов на один анализ** — раздельно по зонам загрузки (не общая сумма): диаграмма + мед.документы — 10, сравнение до/после — 8, протоколы — 12. Иначе Claude рискует не уложиться в лимит времени функции (см. ниже).

### `api/_knowledge.js` — единая база знаний
491 строка. Guardrails (защита от чужих тем/промпт-инъекций), каталог продуктов Coral Club, протоколы по системам, принцип «поэтапного подхода». **Общий для веб-версии и Telegram-бота** — обновляется в одном месте, а не дублируется. Сырые исходные материалы (конспекты по системам/продуктам/протоколам, из которых собран этот файл) лежат в `docs/knowledge/` — это справочные заметки, не код, синхронизируются вручную.

### `api/_partners.js` — единая проверка доступа
Единственное место, где решается «кто это и что ему можно» — до июля 2026 это было продублировано в трёх файлах независимо (см. Фаза 14), из-за чего партнёры, зарегистрированные через Telegram-бота, не видели вкладку «Клиенты». Теперь `auth.js`, `clients.js` и `analyze.js` используют один и тот же модуль.

- Пароль → slug партнёра: хранится в Redis, `HGET partners:passwords <пароль>`
- Токен = `HMAC-SHA256(slug, TOKEN_SECRET).slice(0,32)` — односторонний, восстанавливается перебором известных slug'ов, не декодируется
- `ACCESS_PASSWORD` (env) — резервный бутстрап-пароль для `main`, если Redis ещё пуст; статус этого фолбэка (оставить навсегда или убрать) — открытый вопрос, см. PLAN.md

### `api/auth.js`
Принимает пароль → возвращает `{ mode: slug, token }`. Тонкий слой поверх `_partners.js`.

### `api/clients.js` — мини-CRM
Хранилище клиентов дистрибьютора, с изоляцией по партнёрам (`ns:{slug}:clients:index`, `ns:{slug}:client:{id}` в Redis). У каждого клиента: контакты, статус (один из 8 этапов пути), журнал сессий (каждая привязанная расшифровка добавляется автоматически с датой и текстом разбора — но не исходные скриншоты, см. PLAN.md), опциональные `baseline`/`checkins` для отслеживания самочувствия после начала протокола.

### `api/telegram-webhook.js` — Telegram-бот
Второй канал доступа к системе, параллельный вебу:
- `/start <пароль>` — вход
- `/mypassword` — узнать свой текущий пароль
- `/repassword` — сгенерировать новый
- Одобрение заявок на доступ (`/request-access` от посторонних) — владелец получает кнопки «Одобрить/Отклонить» прямо в Telegram

### `api/request-access.js`
Публичная форма «хочу протестировать» — с рейт-лимитом (3 заявки/24ч на один Telegram-хендл), уведомляет владельца в Telegram.

### `api/cron-checkins.js`
Ежедневный cron (`vercel.json`, `0 5 * * *`) — проверяет клиентов с активным протоколом и шлёт дистрибьютору напоминание, если пора спросить о самочувствии.

## Хранилище данных — Upstash Redis (KV)

Единственная база данных проекта — весь стейт (партнёры, клиенты, сессии, заявки на доступ) лежит в Upstash Redis через REST API (`KV_REST_API_URL`/`KV_REST_API_TOKEN`). Никаких SQL/файловых баз нет.

Ключевые структуры:
- `partners:passwords` (HASH) — пароль → slug, единственный источник правды о том, кто есть кто
- `partner:{slug}:data` (JSON) — активен ли партнёр
- `ns:{slug}:clients:index` / `ns:{slug}:client:{id}` — клиенты, с изоляцией по партнёру
- `req:{id}` / `reqs:pending` — заявки на доступ (TTL 7 дней)

## Обработка ошибок и лимиты

| Ситуация | Что видит пользователь |
|---|---|
| Обрыв потока decode-ответа до конца (таймаут) | Явная ошибка с объяснением — «слишком много скриншотов или сложный кейс», а не тихий пустой результат |
| Превышен лимит скриншотов в зоне загрузки | Всплывающее предупреждение с точным числом лимита — до отправки запроса |
| Неверный пароль/токен | «Доступ запрещён» / «Неверный пароль» |
| Ошибка Claude API | Текст ошибки прокидывается в SSE-поток как `error`-событие |

**Жёсткий потолок:** Vercel serverless-функция `api/analyze.js` ограничена 300 секундами (`vercel.json`, `maxDuration`). Это главный практический лимит системы — большинство решений по производительности (модель, `effort`, лимиты скриншотов, кэширование промпта) существуют, чтобы гарантированно укладываться в это время.

## Деплой

- GitHub: `github.com/valerairon70-hub/tracker-assistant` (старое имя репозитория — `coral-club-ai`, GitHub-редирект на тот же репозиторий, не отдельный дубликат)
- Vercel подключён через Git-интеграцию — `git push` в `main` = автоматический деплой (до июля 2026 деплой шёл вручную через `vercel --prod`, что однажды привело к откату прода на версию 90 коммитов давности)
- `coral-club-ai.vercel.app` — полноценный Domain проекта, автоматически следует за новыми деплоями (раньше был ручной alias)
- Локальная разработка — `dev-server.js`, простой диспетчер `/api/{name}` → `api/{name}.js`, читает `.env.local`

## Зависимости

Фронтенд — без единой npm-зависимости. Серверные функции — только встроенный `fetch`/`crypto` Node.js, без SDK (запросы к Anthropic и Upstash идут напрямую через REST, без `@anthropic-ai/sdk`).
