# Coral Club AI-ассистент — Описание проекта

> Актуализировано 2026-07-24 — описывает то, что реально работает, а не первоначальный план MVP.

## Что это за проект

AI-ассистент для дистрибьюторов Coral Club. Помогает расшифровывать диаграммы трекера здоровья (программа Бутаковой, 12 систем организма) вместе с медицинскими документами клиента (анализы, МРТ, УЗИ) и готовить персонализированные консультации — с протоколом на продуктах Coral Club и готовым скриптом для разговора с клиентом.

Проект строится с позиции нутрициолога и суплементолога: без медицинских диагнозов, но с экспертным объяснением причинно-следственных связей между состоянием систем организма и самочувствием клиента. Инструмент **не дублирует трекер** — протокол уже есть у клиента, задача ассистента — объяснить причинно-следственную связь простым языком и подготовить дистрибьютора к разговору.

## Что уже реализовано

- **Расшифровка** — загрузка скриншотов диаграммы трекера + медицинских документов (анализы, МРТ, УЗИ), жалобы клиента, этап работы, настрой — на выходе разбор причин, протокол, готовый скрипт консультации
- **Блок «Протоколы из трекера»** — загрузка скриншотов существующих протоколов, ИИ синтезирует со своим вариантом из каталога Coral Club
- **Сравнение «до/после»** — как в рамках одного запроса (два набора скриншотов), так и автоматически между первой и последней сохранённой сессией клиента в CRM
- **Вкладка «Пригласить»** — 5 касаний по Кеннеди, сегментация горячий/тёплый/холодный, квалификационный вопрос
- **Вкладка «Статистика»** — мини-CRM: конверсия, история консультаций, CSV-экспорт, напоминания
- **Работа с отказом** — серия касаний для возврата клиента с планированием по датам
- **Вкладка «Клиенты»** — карточки клиентов, 8 статусов пути, журнал контактов, автосохранение сессий из расшифровки, чек-ины самочувствия после начала протокола (ежедневный cron-контроль, напоминание дистрибьютору в Telegram)
- **Вкладка «Кто я?»** — готовые дескрипторы позиционирования + AI-генерация персональных вариантов
- **Telegram-бот** — второй канал входа в систему, выдача/смена пароля, одобрение заявок на доступ от новых партнёров
- **Разделение данных по партнёрам** — у каждого партнёра полностью свои клиенты, свой пароль, никто не видит чужую линию
- **Диагностика перед ответом** — на расплывчатые возражения («дорого», «не верю») система сперва уточняющий вопрос, а не сразу готовый аргумент (см. PLAN.md, Фаза 12)

## Технический стек

| Часть | Технология |
|---|---|
| Фронтенд | Один файл `index.html` (~13 000 строк), чистый HTML/CSS/JS, без фреймворков и сборки |
| Серверные функции | Vercel Serverless (`api/*.js`) — по одной функции на задачу (анализ, авторизация, клиенты, Telegram-бот, cron) |
| AI-модель | `claude-sonnet-5` для расшифровки/чата/сравнения/аналитики, `claude-haiku-4-5` для более простых шаблонных задач |
| База знаний | Встроена в `api/_knowledge.js` — общий модуль для веб-версии и Telegram-бота, не JSON-файлы |
| Хранилище данных | Upstash Redis (KV) — партнёры, клиенты, сессии, заявки на доступ. Единственная база данных проекта |
| Второй канал доступа | Telegram-бот (`api/telegram-webhook.js`) |
| Деплой | Vercel, автодеплой из GitHub (`tracker-assistant`) при `git push` в `main` |

Подробная схема — см. `ARCHITECTURE.md`.

## Правовые рамки

- Ассистент не ставит диагнозы и не заменяет врача
- При серьёзных перегрузах систем — мягко рекомендует обратиться к профильному специалисту
- Работает в рамках методологии и рекомендаций автора программы (Бутакова О.А.)
- Позиционирование: нутрициологическая поддержка, а не медицинская помощь
